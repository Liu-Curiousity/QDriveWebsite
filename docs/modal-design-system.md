# 站内弹窗设计参考规范

提交贡献弹窗（`.account-contribution-dialog:not(.account-redemption-dialog)`）作为站内复合弹窗的首要参考方案。后续替换登录、兑换、资料编辑、审核和设置类弹窗时，先复用这套结构与节奏，再根据内容复杂度调整高度和字段数量。

## 视觉基准

- 弹窗宽度：桌面端 `min(42rem, calc(100vw - 2rem))`；窄屏保留两侧安全距离。
- 高度：由内容自然撑开，使用 `height: fit-content`；最大高度为 `calc(100dvh - 2rem)`，内容超出时只在弹窗内部滚动。
- 外框：`1px` `var(--border-subtle)`，圆角使用 `var(--radius-card)`，背景使用 `var(--bg-elevated)`。
- 阴影：提交贡献弹窗采用无外圈阴影的克制样式；只有在背景层级不足时才使用全局 `var(--shadow-dialog)`。
- 遮罩：使用统一的深色半透明背景和轻微模糊，不在弹窗本体叠加渐变或发光效果。
- 内容板块：浅色模式使用比弹窗主体更浅的 `--modal-control-surface`，深色模式使用更深的同名表面色；输入框、信息块和选项区统一复用该变量，保持主题反向层级。

## 间距与对齐

- 桌面端标题区、说明区和表单内容左右边距统一为 `1.5rem`。
- 移动端统一收缩为 `1.1rem`，不得只缩小标题而保留表单的桌面边距。
- 操作区使用独立的顶部细分隔线，按钮组与内容右边线对齐。
- 表单底部保留 `1.5rem`（移动端 `1.1rem`）内边距，按钮边框不得与弹窗外框重合。
- 内容区使用纵向节奏：字段标签、输入控件、字段组之间沿用现有 `1rem` 左右的间距，不用空行制造层级。
- 关闭按钮固定在标题区右上角，距外框的水平和垂直位置保持一致。

## 结构与状态

推荐结构顺序：

1. 标题区：小型英文眉题、中文标题、关闭按钮。
2. 说明区：一段简短说明，使用次级文字颜色。
3. 表单区：标签、输入控件、附件或辅助信息。
4. 操作区：取消动作在前，主要提交动作在后；主要动作使用唯一强调色。

输入控件保持清晰的默认、悬停、聚焦和错误状态。聚焦状态只提升边框和背景对比度，避免大面积光晕。按钮文字保持水平、垂直居中，按钮宽度由内容和内边距决定。

## 响应式与可访问性

- 弹窗在窄屏不得超出视口；超出内容通过弹窗自身滚动访问。
- 所有弹窗必须保留 `role="dialog"`、可读标题、明确的关闭动作和键盘 Escape 行为。
- `prefers-reduced-motion: reduce` 时取消弹窗进入动画。
- 表单继续保留原生 `required`、`type`、`min` 等约束，并使用现有校验提示机制。

## 实施约束

- 新弹窗优先复用 `auth-control.css` 中的共享 dialog 基础规则和现有语义变量。
- 页面专用样式只负责布局差异，不复制一套新的边框、圆角、阴影和按钮状态。
- 如果弹窗包含列表或历史记录，列表应作为内容区的一部分按内容撑开；只有内容超出视口时才启用内部滚动。
- 完成替换后至少检查桌面宽屏、窄屏、深色主题、键盘焦点和错误提示状态。
