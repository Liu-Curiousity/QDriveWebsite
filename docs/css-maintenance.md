# CSS 维护

## 修改现有外观

先在浏览器中确认实际生效的声明，再修改定义它的规则。替换旧设计时同时删除被取代的声明，不另加一套高权重选择器或 `!important`。一个元素同时匹配基础规则、真实变体和交互状态是正常的；同一个属性经历多次无意义覆盖需要清理。

公共声明可以放在分组选择器中，组件独有属性留在自己的规则里。保留可读格式；移动文件、压缩成一行和删除注释不算完成精简。

## 文件职责

- `site-shared.css`：全站基础、导航、页脚及产品/方案页面。
- `auth-control.css`、`account-page.css`：登录、账户组件与账户页面。
- `web-host-controls.css`：上位机共享控件与按钮；`gimbal-tool.css` 负责 Gimbal 专用布局和轴切换，`serial-assistant.css` 负责 Serial 发送区及 Serial / CAN 共用布局。
- 商城、管理后台、活动等专用文件：维护对应组件，不追加全站覆盖。
- 悬停提示继续复用 `assistant-tooltip.css` 和 `data-tooltip`，见 `ui-tooltips.md`。

## 验证

运行 `npm run check:styles`、`npm run check` 和 `npm run build`。样式检查会识别独立选择器与分组选择器之间的重复声明。涉及跨规则精简时，比较浏览器中的实际布局与计算样式，包含窄屏、深浅主题、焦点、悬停、禁用以及弹窗展开状态。

CSS 的测试不能要求固定注释、分组顺序或空白排版。`tests/css-source.ts` 为声明测试提供按选择器汇总的视图，并保持媒体查询和层的作用域；它不代替浏览器级联验证。

## 上位机字重

Motor、Gimbal、Serial、CAN 共用两档字重：正文、字段标签和辅助说明为 400；标题、按钮、输入框（含多行文本）、下拉当前值及选项、强调信息为 600。共享字重规则位于 `src/styles/web-host-controls.css`，组件中已被合并的声明不要重新添加。字段容器不再以加粗整个容器的方式强调标签；输入与下拉控件共用 600 字重，选项明确使用 600，避免继承外层标签的字重。弹窗标题及 `strong`、`b` 同样遵循 600。全站导航和页脚沿用网站自身规范。

基准为本轮开始时的工作区；统计将新增的 Gimbal 专用文件计入，避免把移动代码计作删除。

| 指标 | 清理前 | 清理后 |
| --- | ---: | ---: |

| 相关 CSS 总行数（共享控件、Serial、Gimbal） | 2,068 | 1,991 |

- 输入控件状态和滚动条状态使用原选择器内的 CSS 嵌套，避免反复列出同一组控件；保持原匹配范围和优先级。
- 删除默认层中已被组件覆盖的属性，保留真正生效的默认值。共享文件内默认层从 391 行降至 276 行；这部分缩减同时包含清理和职责迁移。

- CSS 检查和声明测试支持嵌套状态，并区分基础声明与悬停声明。

验证：四页面、深浅主题、宽窄屏的 48 组样式对比，以及 16 组展开输入区、设备信息、弹窗和连接状态模拟对比。唯一保留的计算属性差异是 Flex 容器上被删除的无效 `grid-template-columns`，不影响布局。动态状态对比无差异。未连接真实硬件。测试 43 项通过、10 项失败；失败项已与本轮修改前的样式基线核对一致，另新增 1 项嵌套规则回归测试。
