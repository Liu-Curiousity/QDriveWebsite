# CSS 维护规范

## 文件职责

- `site-shared.css`：主题变量、基础排版、站点导航/页脚和跨页面组件。
- `auth-control.css`：全站登录、账户菜单、共用账户弹窗和等级徽章。
- 站内复合弹窗统一参考 [弹窗设计规范](modal-design-system.md)，提交贡献弹窗是当前基准实现。
- `account-page.css`：仅由 `account.astro` 引入的账户页面布局、安全表单和响应式规则；在共用账户样式之后加载。
- `web-host-controls.css`：网页上位机共用控件，遵循 [上位机设计规范](web-host-design-system.md)。工具样式只补充各自的布局和业务状态。
- 其他独立样式文件归对应功能所有；Astro `<style>` 保留页面局部布局。

## 修改方式

1. 修改组件现有规则，不在文件末尾继续追加“最终覆盖层”。先搜索该选择器及其媒体查询，确认最终生效的声明。
2. 优先复用 `--bg-*`、`--text-*`、`--border-*`、`--type-scale-*` 等语义变量。页面私有变量使用功能前缀，不能让后台等独立功能依赖账户页面私有变量。
3. 全局组件使用明确的所有权边界。例如页头导航使用 `.site-header > nav`，避免给所有 `nav` 或页头内嵌弹窗的导航施加布局。低优先级默认值可使用 `:where()`，但不要批量改写现有选择器权重。
4. 响应式、暗色、交互状态与基础声明共同维护。不能仅凭重复选择器合并媒体查询，也不能跨条件移动声明；这会改变层叠顺序。
5. 动效明确列出属性，避免 `transition: all`。交互保留键盘焦点样式、`hidden` 行为和 `prefers-reduced-motion` 支持。
6. 不以压缩排版替代重构。不盲目删除 `!important`、兼容性回退或疑似未使用的选择器；动态类名还需检查脚本和模板。

## 验证

运行 `npm run check:styles`、`npm run check`、`npm test` 和 `npm run build`。

样式检查使用 PostCSS 解析独立 CSS 和 Astro 内嵌样式，检查同一条件作用域、同一选择器和优先级下值完全相同的重复声明。`node scripts/check-styles.mjs --fix` 可清理这些声明；它保留后面的规则位置，不合并媒体查询，不改写简写/长写，不处理关键帧和嵌套规则。不同值一律保留，避免破坏函数语法、供应商值和浏览器兼容性回退。该工具不是完整的 CSS 语义验证器，自动修复后仍须审查差异。

涉及共享选择器或资源加载边界时，额外检查首页、账户、后台、详情页及四种上位机的宽屏/窄屏、明暗主题、菜单/弹窗和键盘焦点。后端鉴权保护的内容需要登录状态才能完成视觉验证。
