# CSS 维护

## 修改现有外观

先在浏览器中确认实际生效的声明，再修改定义它的规则。替换旧设计时同时删除被取代的声明，不另加一套高权重选择器或 `!important`。一个元素同时匹配基础规则、真实变体和交互状态是正常的；同一个属性经历多次无意义覆盖需要清理。

公共声明可以放在分组选择器中，组件独有属性留在自己的规则里。保留可读格式；移动文件、压缩成一行和删除注释不算完成精简。

## 文件职责

- `site-shared.css`：全站基础、导航、页脚及产品/方案页面。
- `auth-control.css`、`account-page.css`：登录、账户组件与账户页面。
- `web-host-controls.css`、`web-host-buttons.css`：上位机共享控件与按钮；各工具文件负责特有布局和业务状态。
- 商城、管理后台、活动等专用文件：维护对应组件，不追加全站覆盖。
- 悬停提示继续复用 `assistant-tooltip.css` 和 `data-tooltip`，见 `ui-tooltips.md`。

## 验证

运行 `npm run check:styles`、`npm run check` 和 `npm run build`。样式检查会识别独立选择器与分组选择器之间的重复声明。涉及跨规则精简时，比较浏览器中的实际布局与计算样式，包含窄屏、深浅主题、焦点、悬停、禁用以及弹窗展开状态。

CSS 的测试不能要求固定注释、分组顺序或空白排版。`tests/css-source.ts` 为声明测试提供按选择器汇总的视图，并保持媒体查询和层的作用域；它不代替浏览器级联验证。
